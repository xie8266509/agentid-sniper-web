# 本地 Web 控制台使用说明

基于 [nancy_c813 的 Agent ID Sniper](https://github.com/nancyc0813-maker/agentid-sniper)；原作者 [@nancy_c813](https://x.com/nancy_c813)，Web 增强版维护 [@supra_bnb](https://x.com/supra_bnb)。保留原项目 MIT 许可及第三方许可声明。[GitHub 发布与维护](README.opensource.md)。

已验证 macOS 和 Node.js 24；最低 Node.js 22.15，须通过 Git 克隆仓库。Linux/Windows 的增强版后台服务尚未完成验证。首次配置：

```sh
npm ci
npm run setup
npm run web:start
```

打开 **http://127.0.0.1:4317**。仅监听本机，不暴露到局域网。

根目录 `setup.mjs` 是 `scripts/setup-local.mjs` 的兼容入口，只在配置缺失时生成只读默认配置，不启动服务。旧 Windows 安装/启动入口已停用，仅显示当前支持范围；原脚本保存在 `docs/legacy/*.txt`，不作为可执行安装流程。

当前正式版：**v0.4.2，2026-11-01 发行**；上游基线：**v2.8.1 / `c11d8ef`**。保留多钱包、Web、NFT 规则与正式发行更新渠道，历史见 [变更记录](CHANGELOG.md)。

普通付费项目使用持久化随机进场门槛：进度 60–70%、100–130 个实际发送交易的 Agent ID 钱包，两项同时满足；钱包保存的更高进度从严执行。NFT 至少 70% 进度、150 个参与钱包，进度未知时不自动进入；须存在可读取的每钱包限额声明并核对模拟铸造数量，单笔限量不能替代。完全免费项目只通知；首份免费、后续付费须核验其他成功交易的真实 BNB/USDT 付款，再按付费规则检查。

v2.8.1 起，参与人数须核验 24 小时前已持有 Agent ID、当前仍持有及发送交易次数至少 8 笔。历史状态、当前余额或交易次数读取失败时不计入；不支持历史状态的公共 RPC 可能导致人数较少、延后自动入场。普通及 NFT 自动付费铸造须满足总盘至少 10 BNB、已售至少 500 份或已募至少 5 BNB，且同一项目全部钱包累计投入与未决预占合计不超过总盘 2%；无法核验时等待。

2% 上限针对本工具自动付费铸造；加价和 USDT 补款余量一并计入预占，跨日、重启和更换钱包不重置。单价或当前份数无法核验时等待；旧铸造或已确认文件补打若无法纳入份额账本，会持久暂停该项目后续自动追加，不会仅因下一次 RPC 成功而恢复。手动操作保留，仍须通过原有钱包、模拟及预算检查。任意 Web 或外部手动合约调用不会被猜成铸造任务，也不由此上限代替用户自行核对。

`forceMint` 只优先跟踪，不绕过门槛和免费只通知规则。付费合约核对限额声明、模拟数量、资金留存、代理风险和交易模拟，不再以退款函数作为必要条件。跟单加价最高 20%，完整付款均计入项目和日预算。NFT 单项目累计最多为 10 USD 与配置 `paid.maxUsd` 的较小值，跨日不重置。

已确认付款按真实凭证累计 ERC20 成本；结果不明时保留预占与成本待核验状态，确认恢复后幂等补记。成本未知不套用免费仓卖出规则，也不使用固定猜测 BNB 价格。旧历史若缺少实际付款凭证，不能凭空还原成本。

NFT 元数据/图片检查覆盖受限网络获取、类型识别和本机跨合约字节查重；不保证资产真实、完整可渲染或图片原创。铭文候选只通知，不自动执行。已有 ERC20 与 NFT 持仓的独立卖出规则保留。

新开池持仓按 15 秒目标频率优先检查，复用同一钱包持仓任务及只读卖出模拟，不增加并行卖出入口。只有链上已确认余额为零的持仓使用 30 分钟复查间隔；清仓后重新到账可能等到下一次复查才发现。未决卖出仍优先核对，RPC 或正在运行的任务会影响实际间隔。

v2.8.1 同步：普通扫描、热度与进度轮询覆盖两天内项目，`forceMint` 优先排队但仍通过原有进场和风险检查；被大量部署者规则拒绝的项目避免反复占用轮询。网页地址须为完整 40 位合约地址，通用基础设施或非项目地址不替代真实项目证明，隐藏地址只作受限同源读取和链上核验，不执行网站脚本。

资金留存补充官方 WBNB 与 USDT 余额，USDT 折算须使用本轮可核验的 BNB 报价，未知 RPC 或报价不会推定资金充足；不将任意代币计作资金。这是余额检查，不保证资金可退款、属于项目方或可用于履约。已启用的本地文件补打任务只有匹配的链上成功凭证才标记该钱包已补打，超时确认恢复后也保持幂等；任意 Web 手动合约调用不会被猜成铸造任务。

USDT 自动补款的兑换路由由官方 CLI 选择，Gas 使用保守预留及链上回执核算，不承诺精确预估。费用回执字段缺失时保留风险额度预占，可能需要人工核对，不自动释放。

ERC20 支持新版阶梯减仓、回本后回撤与长抱仓位；已有 `halfX` 配置保留旧策略，可在前端主动切换新版。NFT 使用独立规则，不随 ERC20 策略变化。上游覆盖式 `/update` 已禁用，以免覆盖本地功能；请使用 Web「系统更新」里的合并式一键更新。原有 Flap 交互限制保留。

## 自动检查与一键更新

打开 [系统更新](http://127.0.0.1:4317/#updates)。Web 后台启动时检查一次，之后每 30 分钟检查增强版发行仓库的正式发布标签及 `release.json` 完整文件清单；扫描器停止时仍会检查。默认由「一键更新」触发；可在同页开启「闲时自动更新」。发行来源未配置或校验不通过时停止安装。

用户跟随增强版发行；Nancy 上游由维护者在独立分支审查、合并和测试。增强版版本与上游基线分别记录，不直接用上游单文件覆盖 Web、钱包和 NFT 功能。

更新前须停止扫描器并完成钱包/NFT 操作。更新流程校验候选代码、运行本地回归检查、保存备份，再应用代码并重启 Web；不会自动开启扫描器或交易。Web 启动失败时尝试恢复更新前代码，也可使用「回退上一版本」。配置、钱包会话、NFT 规则、持仓与订单状态不随代码回退。

发行校验不一致、依赖不兼容、候选检查失败，或更新期间源码/暂存区被外部修改时，会停止并保留现有版本。备份、进度与验证日志仅存本机 `data/local_updates/`。回退时若代码已被再次修改，会拒绝覆盖这些改动。Git 克隆是首发验证的安装方式，ZIP 安装暂无一键更新保证。

## 闲时自动更新

更新页的开关默认关闭，设置单独保存在私有 `data/local_updates/idle-settings.json`，不修改交易配置或要求重启扫描器。开启后每分钟评估已核验的增强版正式 Release；发行检查仍为启动时及每 30 分钟。

安装条件：扫描器已停止；没有钱包登录、预演、交易或待核对记录；没有未结算额度预占；NFT 无活动挂单、签名或待核对订单；源码、暂存区及未跟踪发行源码无修改；连续空闲至少 60 秒。已有持仓本身不妨碍更新。外部项目钱包操作和扫描器最近活动也会延后安装。

自动安装复用一键更新的候选验证、备份、钱包排他、Web 重启健康检查及失败回退。维护屏障覆盖源码替换和重启恢复，阻止项目扫描器及新钱包任务启动；已开始的钱包任务完成前不会安装。不会主动停止运行中的扫描器，也不会自动恢复扫描器或开启交易。

同一目标提交只自动尝试一次，失败或中断后需查看日志并手动处理；关闭再开启不清除尝试记录。关闭开关可取消尚未应用的自动安装；已写入的版本不会因此撤销，可手动回退。配置损坏、源码冲突、未明提交、维护记录或健康恢复无法核对时暂停。

## 上游监测与发行自动化

GitHub Actions 的 `Check upstream and prepare review` 按每 15 分钟目标频率检测 Nancy 上游版本与提交（GitHub 定时任务可能延迟）。发现变化后，生成以完整 SHA 固定的差异、三方分析和适配清单，去重建立 Draft PR；只验证当前增强版及审核资料。**该 PR 不代表上游新增交易行为已完成适配。** 钱包、交易、预算、NFT、依赖和更新逻辑仍需兼容修改、测试与审核后合入 main。

审核完成后，在 Actions → `Publish reviewed release` 选择 main，填写 Web 版本（不含 v）、完整 main 提交 SHA 并勾选已审核；工作流运行全量测试、发行清单及敏感模式检查后，为同一提交创建稳定标签和 Latest Release。main 变化、测试失败或标签指向不符时停止。无需额外 Secret。

Actions 需允许创建 PR；如果仓库禁止该能力，监测会报告权限问题，不会改写 main 或绕过权限。上游原仓库不会直接覆盖本机增强版。

## 旧版更新器的一次迁移

v0.2.2 修复了本机时钟较慢或 GitHub 发布时间偏移时，已正式发布的版本被误判为不可安装的问题。日期仍须有效，但发布资格不再由本机时间比较决定。来源、稳定标签、标签提交、完整文件清单和候选测试继续校验。

旧版（≤ v0.2.1）的旧判断须通过升级代码修复，无法仅靠发布新 Release 改变。源码干净的官方 Git 克隆安装，可完成待处理交易、停止扫描器后执行一次：

```sh
npm run web:stop
git fetch origin tag v0.2.2
git merge --ff-only v0.2.2
npm run release:prepare -- --check
npm run release:check
npm run web:start
```

有未提交源码修改或无法快进时，先保留并整合修改；不要强制覆盖。本机配置、会话、持仓和 NFT 数据不参与代码合并。完成这一次迁移后，后续 Release 发布即可检查并获取，不需调时钟或等待一小时。

## 页面功能

- 运行概览：区块、扫描落后量、心跳、近期项目，启动／停止／重启监控。
- 钱包中心：直接创建钱包、生成官方配对链接，手机核对配对码并确认，再核验绑定真实 BSC 地址；查看连接、权限、执行状态、预算与待核对操作。
- 策略配置：全局自动总闸、全部钱包预算、Telegram、全局策略模板、手动持仓和指定铸造合约；每钱包可设置独立预算、进场与 ERC20 止盈规则。保存后查看页面的实际生效状态；从只读扫描切换自动模式须明确启动自动扫描。
- 持仓追踪：每 15 秒刷新，NFT 当前数量从链上只读核验（缓存 90 秒，手动刷新可重新核验）。新增 Element 参考地板价、累计成交量与官方挂单入口（市场缓存 5 分钟）。挂单链接使用当前钱包已核验的 NFT ID；未知价格和数量不记为零。ERC1155 只统计已识别 ID。进入页面自动读取选中钱包的 BSC 余额。
- 止盈生效状态：对比已保存与扫描器实际加载的规则，并显示 ERC20 尚未触发的原因。NFT 有独立的自动卖出配置与执行状态。免费 ERC20 在开池 3 分钟后采样峰值，持仓估值至少 $0.30 才触发回撤卖出。
- 手动操作：指定钱包、BSC 合约、calldata 与 BNB 数量，先预演，展示原钱包名称、完整地址、资产变化和风险，再确认发送。预演绑定钱包身份与配置，切换钱包或配置改变后须重新预演；过期、执行后不可重放。NFT 授权、卖出和撤单确认同样固定原钱包。
- 运行日志：搜索、自动刷新、导出最近日志。

开发者模式须在币安 App → Agentic Wallet → 设置开启；控制台只能查看状态。实际登录确认与链上交易由用户完成。

## 钱包中心

点击「添加钱包」→「创建并配对」→在对应币安 App 核对配对码→核验并绑定 BSC 地址。绑定时读取官方返回的已领取 Agent ID handle，未领取时留空；显示名称不能代替真实 Agent ID。每个新钱包默认 `mode: monitor`、`paused: true`、每日付费预算为 `0`，绑定成功也不自动启用交易。

旧钱包的备注可能不是官方身份，升级后会显示「Agent ID 待核验」。在连接详情点击「核验 Agent ID 与地址」即可读取官方结果；无需重新配对已连接的会话。未核验的备注不会作为合约 Agent ID 参数，尚未领取时保留空值，领取后可再次核验。

最多配置 16 个钱包。每个钱包有不可变 `walletId`（配置字段为 `id`），旧配置迁移时固化原 `bawDir` 和 `instanceId`，不移动原加密会话。改名、重排不会更换身份或重置额度。归档代替删除，保留会话、预算和订单；有未决交易或 NFT 挂单时不能归档，恢复后保持暂停。

顶部选择「全部钱包」或单个钱包，统一筛选 ERC20、NFT、策略状态、交易记录和资产余额。钱包页可批量暂停、复制全局模板；复制 `paid` 和 `rules` 不改变模式或暂停状态。钱包独立保存的字段优先于全局模板，未覆盖字段沿用全局值；NFT 价格和成交规则仍按钱包及资产单独配置。

同一钱包的登录、预演与交易串行执行，默认最多两个钱包同时进行预演或交易。配对弹窗固定所选钱包，切换后丢弃旧响应。**当前本地测试不代表 2–3 个真实币安账号同时在线的实盘流程已验证。**

NFT 地板价是系列最低挂牌参考，不是可立即成交的买方报价；部分系列没有公开报价、可能没有买家，或合约限制转让。卖出须在市场核对资产、价格、授权与签名。公开页面结构变化或网络失败时显示暂无报价，不捏造最近成交价或出价。

ERC20 持仓检查独立于新项目分类运行，繁忙时不重复启动同一轮检查。卖出按真实代币精度计算数量，以原始持仓数量归一化价格，避免减仓后误判回撤。新版策略的回撤需要连续两次有效报价确认；回本后的长抱保留量仅在成交核验后生效。提交前持久化卖出意图，等待订单终态与该笔交易凭证核验后才推进止盈阶段。提交结果不明、部分成交或无法归因时暂停该仓位自动重发，在页面提示核对订单；不会将“提交成功”当作“已成交”。

## NFT 自动卖出与止盈

在持仓行点击「自动卖出规则」，或在策略配置页的「NFT 自动卖出」集中管理。按钱包、合约和 Token ID 设置，金额使用 BNB 精确小数字符串，支持：

- 固定价挂牌：填写每件挂单价、整笔最低净收入、费用与预估 Gas 上限、数量和订单有效期。
- 目标止盈：仅在可执行买单的预计净收入达到目标时接单。
- 跟踪止盈：有效买单净收入先达到启动价，再从已采样峰值回撤设定比例，且仍满足保底净收入时接单。

草稿默认停用。先在本地设置 Element API Key（[官方 NaaS](https://element.market/naas)，发布能力取决于订阅权限），再核对具体资产、数量和价格边界并确认启用。Key 只写本机 `data/nft_market_settings.json`，不回显到网页；也可通过进程环境 `ELEMENT_API_KEY` 提供。规则与订单状态分别存储于 `data/nft_rules.json`、`data/nft_trading_state.json`，均私有写入并被 Git 忽略。

NFT 工作器随 Web 后台服务运行，每 15 秒检查；须同时满足扫描器处于自动交易运行状态、全局允许自动执行、钱包未暂停或归档、模式允许卖出且 `autoSellNfts` 开启，才创建新订单。无需为独立 NFT 规则重启扫描器。需登录钱包并开启开发者模式；NFT 初次授权必须单独预演确认（ERC721 仅授权单 Token ID，ERC1155 授权覆盖整个系列）。钱包要求确认或预演包含未知风险时等待人工操作，不静默执行。

**NFT 真实挂牌与成交尚未完成完整实盘验证。** 当前仅支持 BSC ElementEx 普通固定价挂牌、可完整核验的单品 WBNB 买单；不执行未知聚合器、任意回调、系列/属性买单或非 BNB/WBNB 付款。可执行编码、签名、买方余额、授权、费用与实际模拟资产变化均须通过检查；地板价不会触发接单。收入可能为 WBNB，不会额外自动兑换。Gas 按当前网络估算并加缓冲，链上实际值仍可能变化。

签名/交易提交前先严格持久化意图，最终按精确订单及本笔链上 NFT/收款事件确认。发布回执字段不完整、部分成交、响应中断或无法核验时转待核对，禁止自动补卖或重发。停用只停止新动作；如有已签名挂单，应使用「撤单预演」核对后撤销，确认撤单同时停用规则。不要删除状态文件来重试不明订单。

## 运行模式与预算

默认 `monitorOnly: true`，全局禁止发起自动铸造和买卖。手动操作仍使用独立的预演、确认流程；已提交订单继续按原记录核对。自动执行还须满足钱包已绑定、未暂停或归档、运行中的扫描器允许自动交易，并符合以下模式及功能开关：

| 字段 | 含义 |
| --- | --- |
| `mode: monitor` | 只监控，不发起新自动交易 |
| `mode: sell-only` | 允许卖出，不参与铸造或买入 |
| `mode: auto` | 按已启用功能和规则自动执行 |
| `paused: true` | 停止此钱包的新自动操作，不撤销已发送交易或 NFT 挂单 |
| `autoMint` / `autoSellTokens` / `autoSellNfts` | 分别允许自动铸造、代币卖出、NFT 卖出；受总闸、模式与暂停状态约束 |

全局总闸关闭会阻止所有钱包的新自动交易；打开总闸不会解除新钱包的默认暂停。应用钱包自动规则须单独核对地址、权限、预算和功能开关。

`paid.maxUsd` 是单项目付费铸造预算；NFT 同钱包同合约按历史累计核对。`paid.dayUsd` 是每钱包每日美元上限，默认 60、可设 0–60；`paid.maxBnbPerDay` 是每钱包每日 BNB 等值付费上限；钱包的 `paid` 可独立覆盖全局模板。付费铸造包含已有 USDT 的等值和为铸造充值 USDT 的实际 BNB。任一上限为 `0`，付费铸造关闭。

`portfolioBudget.maxBnbPerDay` 是全部钱包的每日付费总上限：`null` 表示未设置总限额，`0` 表示禁止付费操作，正数须与每钱包额度同时满足。示例配置保持空钱包、全局只读、每钱包默认日预算 `0`，总上限为 `null`；这不会自动允许交易。手动发送 BNB 也核对钱包及总额度。免费铸造的 gas 不包含在付费铸造日预算内；含防女巫等 BNB 手续费的铸造计入付费预算；卖出兑换不使用付费铸造预算。

发送前以同一原子账本预占美元与 BNB 额度，实际结算计入真实支付。旧账本当天已有 BNB 花费但缺少美元价格依据时，从严占满当天美元额度；旧未决预占也占额度，不能猜价格释放。手动 BNB 付款若无美元价格依据，同样从严占满当日美元额度，可能暂停后续自动付费。页面区分已花费、预占与剩余。结果不明时保留预占，跨日也不自动释放；改名、重排、暂停或重启不能清除待核对记录。恢复只接受原提交已关联的交易哈希，或官方订单关联的哈希，再匹配钱包、链、合约、数量/调用和链上收据。任意相似历史交易哈希不能解锁。证据不足时继续等待，不自动重发，也不要删除本地状态文件重试。

公共 RPC 下，候选项目分类可能耗时数分钟。页面的扫描落后量来自最近完成的一轮采样，可结合心跳时间判断新鲜程度。

上游新增的 `data/manual_mint.json` 文件指令默认关闭。只有显式设置 `enableFileCommands: true` 且处于自动模式时才消费，任务须使用 `schemaVersion: 1`；铸造任务仍受单笔／日预算及预演检查约束，最多连续 10 份。Web 手动预演确认流程保持可用。

## TG 已选群线索 · 可选

默认 `telegramUser.enabled: false`，关闭时不加载 SDK、不登录、不读取群消息。需要时由你在本机终端执行：

```sh
npm run setup:telegram -- --install
npm run setup:telegram -- --login
```

可选依赖固定 `telegram@2.26.22`，单独安装至 `data/telegram_runtime/`，不改变主项目依赖。登录在交互终端中输入自己的 Telegram API ID/API Hash、手机号、验证码和两步验证；手动选最多 12 个已加入的群/频道。会话与所选 peer 仅写入本机私有文件 `data/tg_user/session.json`，不经网页回显。

在全局策略页填入选定的群 ID 并启用。Web 后台约每分钟轮询；首次仅读最新 1 条定位、不收集历史，重启重新收集计数。只访问明确选中的群，运行期不枚举群组、不发消息、不自动加入群。切换或撤销群选择会清除旧候选计数。候选文件只保存规范化地址/网址与匿名计数，不保留消息正文、用户或群名；网址会去掉查询参数，仍可能暴露候选项目来源，因此该文件保持本机私有。

普通合约须出现于至少 3 个所选群；网址须至少 2 群或 3 个发送者。可设置 `telegramUser.vipGroupIds` 为已选群 ID 的子集，重点群可提前检查，每小时最多 30 个优先候选，配额持久化，改名或重启不会重置。所有候选仍须真实链上 Agent ID 参与者检查。无合约的热门网址每 2 分钟重试、最多 2 小时，网络读取及每轮核验都有上限。同名合约只能产生关联待核对通知，不据此加入自动跟踪。群信号仅加速发现，不能授权交易或绕过钱包、进度、预算与模拟检查。本版只用假客户端验证隔离流程，尚未进行真实 Telegram 登录监控验证。

## 钱包报错修复

原官方 CLI 的系统钥匙串槽位由多个实例共享，仅设置 `BINANCE_BAW_DIR` 不能隔离会话，可能造成会话与客户端标识混用。现在 Web、`login.mjs` 和扫描器统一使用项目内官方 CLI，以及各自独立的加密会话文件，避免复用全局会话。

已验证独立环境正常返回 `UNCONNECTED`，并能真实生成币安登录链接。具体旧全局会话的 `illegal parameter` 原因无法唯一确定；全局安装与会话未被重置。需在控制台重新登录，只有本地状态 `CONNECTED` 才表示登录完成。

## 管理命令

```sh
npm run web:start       # 后台启动控制台
npm run web:status
npm run web:stop
npm run monitor:start   # 后台启动扫描
npm run monitor:status
npm run monitor:stop
npm test
```

在已验证的 macOS 环境中，关闭终端后后台服务继续运行，工作进程退出后自动重启。注销或重启电脑后需重新启动；电脑须保持联网。`WATCH_STOP` 文件可停止扫描，`WEB_STOP` 可停止控制台；对应 `start` 命令会清除标记。

配置 `config.json`、会话 `data/wallets/` 和运行数据 `data/` 均被 Git 忽略。Telegram Token 仅写入本机配置，不回显到网页；留空保留原值，勾选清除后删除。日志在 `data/watch.log`，控制台诊断在 `data/web_console.log`。
