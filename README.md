# Agent ID Sniper Web

**v0.4.7 社区 Web 增强版 · 2026-11-01 正式发行**：在本机管理多个 Binance Agentic Wallet 的 Agent ID 铸造监控、持仓和卖出规则。

基于 [Nancy 的 Agent ID Sniper](https://github.com/nancyc0813-maker/agentid-sniper)。原作者 [@nancy_c813](https://x.com/nancy_c813)，Web 增强版维护 [@supra_bnb](https://x.com/supra_bnb)。这是社区维护项目，不是 Binance 官方产品。

## 功能

- 总览与钱包页显示实际 BNB/USDT 余额，已绑定的离线钱包也可读取；至少一个已授权且可用的钱包即可启动，其余单独跳过，运行中失联仅暂停对应钱包。
- 同步上游 v2.8.2：每钱包每日最多 60 USD，NFT 更严门槛；完全免费项目只通知，首份免费、后续付费按已验证付款识别。保留多钱包执行、成本记录和原子预算。
- 参与人数只计历史与当前 Agent ID、交易次数均可核验的钱包；自动付费铸造检查小盘和全钱包累计 2% 上限，新开池优先检查与常规持仓共用执行保护。
- 新开盘快仓优先检查价格，在旧仓之间补查到期快仓；同一钱包顺序推进，避免快查和完整检查重复执行卖出阶段。
- 可选 TG 已选群线索监控，默认关闭，需用户在本机手动安装依赖、登录并选群；候选还须通过链上检查。
- 钱包中心始终管理全部钱包，可直接创建、App 配对、核验绑定；顶部筛选继续作用于持仓、策略与交易记录。
- 每个钱包使用稳定 `walletId` 和独立 CLI 会话；旧钱包保留原会话目录与 `instanceId`，改名或重排不更换身份。
- 全局自动总闸与每钱包模式、暂停和功能开关共同控制执行；钱包预算和 ERC20 规则可独立配置或复制全局模板。
- ERC20 精确数量卖出、阶梯止盈与长抱；按订单和本笔链上凭证确认结果，未知结果停止自动重发。
- NFT 链上持仓核验、Element 参考地板价、固定价挂牌、目标净收入与跟踪止盈规则。
- 重复买入成本按已确认交易累计，同一哈希不重复计费；资金留存检查补充官方 USDT/WBNB，未知价格继续从严处理。
- 重点群线索、热门 URL 有限重试、两天内项目与新热门项目优先；身份、进场、预算和模拟检查保留。
- Web 启动及每 30 分钟检查正式 Release，一键更新/回退；新增默认关闭的「闲时自动更新」。
- GitHub 每 15 分钟检测上游，准备固定差异与兼容审核 PR；适配审核后可一键运行自动验证和发布。

## 安装

**已验证：macOS、Node.js 24、Git。** 运行最低版本为 Node.js 22.15。Linux、Windows 尚未完成增强版验证，后台服务和一键更新依赖 POSIX 进程管理。

发行仓库：[xie8266509/agentid-sniper-web](https://github.com/xie8266509/agentid-sniper-web)。从 Git 仓库安装：

```sh
git clone https://github.com/xie8266509/agentid-sniper-web.git
cd agentid-sniper-web
npm ci
npm run setup
npm run web:start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。控制台只监听本机。

`setup` 会安装项目内的 Binance 官方 CLI，并在配置不存在时创建只读默认配置：空钱包、`monitorOnly: true`、每钱包每日付费预算为 `0`，`portfolioBudget.maxBnbPerDay: null` 表示未设全部钱包总上限。已有配置会保留。启动 Web 不会自动启动扫描器或启用交易。

首次使用，在「钱包」点击「添加钱包」→「创建并配对」，用对应币安 App 核对配对码，再核验并绑定真实 BSC 地址。已领取的 Agent ID 使用官方返回的真实 handle，未领取时留空。新钱包默认不勾选暂停（`paused: false`），绑定后仍为 `mode: monitor`，不会自动启用；手动选择的暂停状态保持不变。需要签名或交易时，在 App 的 Agentic Wallet 设置中开启开发者模式。项目不要求输入私钥或助记词。

首发使用 Git 克隆安装；Download ZIP 缺少 `.git`，不承诺一键更新可用。根目录的旧 Windows 安装/启动入口已停用，只显示支持范围和 README 提示；原脚本已作为不可执行的文本归档于 [docs/legacy](docs/legacy/)。这些入口不会安装依赖、启动扫描器或执行交易。

## 多钱包与启用策略

先核对钱包、单项目、每钱包每日预算和全部钱包总预算，再打开全局自动总闸、选择钱包模式并解除暂停。`monitor` 只监控，`sell-only` 仅允许卖出，`auto` 按规则自动交易；`autoMint`、`autoSellTokens`、`autoSellNfts` 可分别关闭。手动与 NFT 预演、确认固定原钱包，切换钱包后需重新预演。

总预算 `portfolioBudget.maxBnbPerDay` 为 `null` 时不设总限额，为 `0` 时禁止付费操作；仍受每钱包预算限制。发送前原子预占额度，不明结果保留预占并阻止自动重发；默认最多两个钱包并发，同一钱包串行。归档保留会话、额度和订单；有未决操作时须先核对。暂停不撤销已签名 NFT 挂单，须单独撤单。首次 NFT 规则保存为停用草稿，启用和初次授权需要单独确认。

当前本地测试不代表已验证 2–3 个真实币安账号同时在线实盘。

NFT 自动卖出需要具备相应权限的 [Element API Key](https://element.market/naas)，钱包须可用并满足预演要求。目前支持 BSC ElementEx 普通固定价挂牌和可完整核验的单品 WBNB 买单（收入按已验证编码可为 BNB 或 WBNB）；未知编码、额外授权或无法核验的结果会暂停。没有有效买单时等待，不用地板价代替可成交报价。**NFT 真实挂牌与成交尚未完成完整实盘验证。**

付费铸造同时受美元、BNB 与全部钱包预算约束，加价计入额度。未知成本不会按免费仓执行卖出。元数据与图片检查仅覆盖可获取性、类型识别和本机字节查重，不保证项目真实或图片原创。

金额、预算、风险和当前支持范围见 [本地使用说明](README.local.md)。

## 更新与回退

「系统更新」随 Web 后台运行，启动时及每 30 分钟检查增强版的正式发布标签和 `release.json` 完整文件清单；默认由用户点击安装；也可在更新页开启「闲时自动更新」。发行仓库尚未配置时，不安装未知来源的代码。

闲时安装要求扫描器已停止、没有未决钱包/NFT 操作或活动挂单、源码与暂存区干净，并持续空闲至少 60 秒。它会等待，不主动停止扫描器。同一提交失败或中断后暂停自动重试，需手动核对。

更新前停止扫描器并完成钱包/NFT 操作。候选版本通过校验和本地回归检查后，保存备份、应用代码并重启 Web；启动验证失败时尝试恢复旧代码。回退不恢复或覆盖钱包会话、配置、持仓和订单数据，也不会自动开启交易。冲突、发布校验不一致或更新期间出现外部源码改动时会停止并显示原因。

v0.2.2 起，正式发行是否可用由 GitHub 发布状态、标签提交及完整源码清单确认，不用本机时钟判断发布时间；发布后无需等待时差。旧版客户端须先升级一次至 v0.2.2，之后正常使用一键更新，见 [一次迁移说明](README.local.md#旧版更新器的一次迁移)。

Nancy 上游变更由维护者在独立分支合并，经审核和 CI 后发布增强版；用户更新不直接覆盖为上游的 `watch.mjs`。增强版版本和上游基线分别记录。

## 管理命令

```sh
npm run web:status
npm run web:stop
npm run monitor:status
npm run monitor:stop
npm test
```

建议通过 Web 明确启动扫描器。退出登录或重启电脑后，按需重新启动 Web；首次发行不配置系统开机自动运行。

## 本机数据

`config.json`、`data/`、钱包会话、市场 Key、运行日志、订单状态和更新备份均保存在本机，并被 Git 忽略。不要把这些文件或未脱敏日志提交到 Issue、PR 或仓库。保留订单状态文件，不要通过删除它来重试结果不明的交易。
